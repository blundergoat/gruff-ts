## v0.4.0 - 2026-06-11

- **Circular imports group by SCC** - `design.circular-import` reports one finding per strongly connected component (member list in `metadata.files`); circular-import fingerprints and hook identities intentionally churn (ADR-015). OpenUI dropped from 108 findings to 3.
- **Cycles stay visible in scoped scans** - narrow path scans build root graph context for the circular rule only, and changed-region and hook runs keep a cycle when any member file changed.
- **Scan-surface notes** - reports gain an additive `notes` field: `no-analysable-files` for paths with nothing analysable, `bounded-deep-scan` for huge files that keep text rules but skip deep passes. Notes name their file; diagnostics still own exit 2.
- **Generated-source policy** - explicit generation markers (`@generated`, `DO NOT EDIT`, ...) suppress documentation and naming findings only; every other pillar still runs.
- **Real TypeScript parse diagnostics** - the TypeScript syntax parser replaces the delimiter heuristic, so valid TSX no longer false-positives and real syntax errors keep exit 2.
- **Sensitive-data precision** - exempts word-segment identifiers, character-set alphabets, code-expression env values, Luhn digit runs without card vocabulary, and explicit fake markers (`EXAMPLE`, `REDACTED`, ...); real secrets still flag.
- **Security and test-quality tuning** - `security.sql-concatenation` covers `prepare(...)`, validation-only publish gates stop flagging `security.risky-lifecycle-script`, `security.process-exec` carries `callName`/`argumentSource`/`shellEnabled` hints, and static-import test sentinels downgrade to review guidance.
- **`dead-code.unused-private-method`** - bare `this.method` references count as usage; unrelated properties sharing the name no longer mask an unused private method.
- **Execution-level rule gating** - rules disabled by config or profile now skip their scanner passes instead of filtering findings afterwards, and the comment-quality gate no longer silently disables `docs.fixture-purpose-missing`.
- **Hook efficiency** - changed-region hook runs reuse one analysis pass; the diff/since new-only replay stays a second pass and materializes every SCC member, so pre-existing cycles are not reported as new. vscode-scale repos still need the minimal profile.

## v0.3.2 - 2026-06-09

- **Agent-hook contract v1** - adds `gruff-ts hook` and `gruff-ts hook --capabilities --format=json`, advertising `gruff.hook.v1` with `flagOrder:"any"`. Hook JSON uses the cross-analyzer contract fields (`file`, `scope`, `suppressed.count`, `ignored.paths`, `config.error`) with non-null remediation, stable hook identities, and machine-readable threshold metadata. Hook mode exits `0` when analysis runs, omits file/project-scope findings under changed-region attribution, and uses stable identity for baseline/diff new-only filtering (`--diff unstaged` compares against the index, `suppressed.count` never double-counts a re-emitted finding, and distinct project-scope findings such as separate import cycles anchored to one file keep distinct identities so baselining one never suppresses another). Operational failures (missing/malformed baseline, `--diff`/`--since` outside a git repo) report in-band as `config.error` with exit `2` rather than crashing. The conformance tests cover capabilities, scopes/enums, remediation, threshold metadata, stable identity across line/value changes (including multiple same-rule findings in one file and distinct import cycles sharing an anchor file), baseline and diff new-only, operational-failure JSON, flag ordering, advisory exit, ignored paths, and config-error JSON. Existing `analyse` / `summary` / `report` schema versions and exit semantics are unchanged. (`src/hook-contract.ts`, `src/cli-program.ts`, `src/hook-contract.test.ts`)
- **Changed-region symbol scope drops inherited file-wide findings** - `--changed-scope symbol` now suppresses file-wide and file-aggregate findings when the changed range does not touch their anchor/span, so inherited debt such as `size.file-length` is counted in `suppressedCount` instead of reported on unrelated edits. Use `--changed-scope file` for CI workflows that intentionally want every finding from a touched file, including deletion-only edits. Full scans still report every file-wide finding. No severity, threshold, rule-id, or pillar change. (`src/changed-regions.ts`, `src/changed-region-scope.test.ts`, `src/changed-region-contract.test.ts`)
- **Threshold findings expose reviewable measurements** - `size.file-length`, `size.function-length`, `size.parameter-count`, `complexity.cyclomatic`, `complexity.cognitive`, `sensitive-data.high-entropy-string`, and `sensitive-data.hardcoded-env-value` now carry additive `measured`/`threshold` measurement metadata, and block-anchored findings carry `endLine` spans so hook output can attribute symbol-scope findings without message parsing. `size.file-length` also gets finding-level remediation from the descriptor text. Existing fingerprints stay stable. (`src/analyser.ts`, `src/blocks.ts`, `src/findings.ts`, `src/sensitive-data-rules.ts`)

## v0.3.0 - 2026-05-30

0.3.0 release. Changes since 0.2.0: three breaking rule removals (`complexity.npath`; `size.stylesheet-length` with CSS dropped from scanned file types; and the `design.god-function` composite), region-scoped incremental analysis, authoritative `paths.ignore` with a new `check-ignore` command, sensitive-data PHI/GCP detection, named config profiles with `extends:` inheritance, and a documentation reframe around gruff's purpose - governing AI-generated code so a human who did not write it can sign off on it.

- **BREAKING: removed `complexity.npath`** - the rule and its `approximateNpath` helper are deleted; the complexity pillar is now `cognitive` + `cyclomatic`. Its `2^(decision tokens)` model false-flagged flat switches and guard-chains (easy-to-verify code) and its remediation pushed agents to fragment legible dispatch, while `cognitive` already covers genuine complexity (ADR-005, ADR-006). The `docs.missing-why-for-complex-code` gate drops its npath term (now size/cyclomatic/cognitive/nesting). No schema change (`gruff.analysis.v2` unchanged), but `list-rules`, reports, and findings no longer include `complexity.npath`, and a stale `rules.complexity.npath.*` config block is silently ignored. (`src/rules.ts`, `src/blocks.ts`, `src/context-doc-rules.ts`)
- **BREAKING: removed `size.stylesheet-length` and dropped CSS from scanned file types** - `.css` files are no longer discovered or analysed, and the CSS-only `size.stylesheet-length` rule (with its `isCssPath` gate) is deleted; the `size` pillar drops to 3. The rule could only ever fire on `.css` files, so dropping CSS scanning left it dead - same shape as the npath removal. No schema change (`gruff.analysis.v2` unchanged), but `list-rules`, reports, and findings no longer include `size.stylesheet-length`, and a stale `rules.size.stylesheet-length.*` config block is silently ignored. (`src/discovery.ts`, `src/analyser.ts`, `src/rules.ts`, `.gruff-ts.yaml`)
- **BREAKING: removed the `design.god-function` composite** - the rule and its `pushGodFunctionFinding` emitter are deleted; the `design` pillar drops from 6 to 5 and the catalogue from 120 to 119 (still 11 pillars). It fired only when a function was both long (>45 lines) and complex (cyclomatic >10) - a synthetic restatement of the `size.function-length` + `complexity.*` findings already on that symbol, whose only honest score is neutral once ADR-009 clusters those findings into one penalty. `design.god-function` is dropped from `CORRELATED_COMPLEXITY_RULE_IDS` while `complexity.cognitive`, `complexity.cyclomatic`, and `size.function-length` stay, so a long-and-complex function still moves the grade once with every finding listed - P5 now rests on that clustering, not on a named composite. Family-wide retirement of the `design.god-*` composite (gruff-rs removed it first); the named god-function signal is the only loss. No schema change (`gruff.analysis.v2` unchanged), but `list-rules`, reports, and findings no longer include `design.god-function`, and a stale `rules.design.god-function.*` config block is silently ignored. (ADR-011, ADR-009; `src/rules.ts`, `src/blocks.ts`, `src/scoring.ts`, `src/report-renderers.ts`)
- **Named config profiles with `extends:` inheritance** - a `profile:` block (or `--profile` flag) selects a bundled rule set instead of enumerating every rule by hand. Three built-ins ship with the binary: `gruff.minimal` (security and sensitive-data only), `gruff.recommended` (every pillar at its defaults - byte-identical to a zero-config scan), and `gruff.strict` (every pillar with tightened size, complexity, and secret thresholds). The inline form extends a built-in name or a relative profile file and overrides individual rules or ignored paths, with deterministic child-wins flattening (per-rule fields merge; `ignoredPaths` arrays replace). Precedence: `--profile` flag > config `profile:` > the `extends:` chain > the default `recommended`; a top-level `rules:` entry still overrides the profile. Unknown built-in/file, `extends:` cycles, and rule ids outside the catalogue all error at load time - file paths only, no remote URLs or shell. New `list-profiles` command plus `--profile <name-or-path>` on `analyse`/`report`/`summary`/`dashboard`. Config-only: no `gruff.analysis.*`/`gruff.baseline.*` schema change. The zero-dependency YAML parser and value-narrowing helpers moved from `src/config.ts` to a new `src/config-parse.ts` so the config module stays legible. (ADR-010; `src/profiles.ts`, `src/config.ts`, `src/config-parse.ts`, `src/cli-program.ts`, `src/rule-list.ts`, `src/types.ts`)
- **Region-scoped incremental analysis** - lets a coding agent run gruff-ts as a hook on only the code it changed, not the whole repo, so it resolves findings in its own diff before a human reviews and a clean change is never blocked by pre-existing findings elsewhere. `--changed-scope <symbol|hunk>` narrows findings to changed code: `symbol` reports findings whose enclosing declaration changed, `hunk` only those on changed lines. Driven by `--changed-ranges "<start>-<end>,..."`, `--since <ref>`, or `--diff` (including `git diff | gruff-ts analyse --diff -`). JSON keeps the normal `findings` array and adds `suppressedCount` when region filtering is active, so a PR check can gate on "did this change introduce findings?" without a baseline file. (`src/changed-regions.ts`, `src/analyser.ts`, `src/cli-program.ts`, `src/types.ts`)
- **Region-scoped analysis hardening** - diff-scoped runs now keep full project context for cross-file rules before filtering emitted findings, so central tests/import graphs remain visible while unchanged findings are still suppressed. Piped unified diffs track actual added target lines instead of hunk-header spans, deletion-only hunks no longer create target ranges, base-ref diffs no longer pull in unrelated untracked files, custom refs are passed after `--end-of-options`, file-wide findings stay visible when any hunk touches their file, and `export default class` bodies participate in symbol-scope matching. (`src/analyser.ts`, `src/changed-regions.ts`)
- **`paths.ignore` authoritative everywhere + `check-ignore` command** - config `paths.ignore` now excludes a path in every invocation shape, not just the directory walk: explicit file operands (`gruff-ts analyse src/generated.ts`) and diff/changed-region runs honour it too, so a coding-agent hook stops surfacing findings for deliberately-excluded files. `--include-ignored` opts into git/default ignores only and never overrides `paths.ignore`. The report's `paths` gains an additive `skipped: [{ path, source, pattern }]` array (`gruff.analysis.v2` unchanged; `ignoredPaths` kept as the back-compatible `string[]`). New `gruff-ts check-ignore [--format text|json] <paths...>` reports per path whether gruff would ignore it and by which source+pattern, sharing the exact ignore engine as `analyse` (no second matcher) and mirroring `git check-ignore` exit codes (0 = at least one ignored, 1 = none, 2 = error). (ADR-007, M27; `src/discovery.ts`, `src/check-ignore.ts`, `src/cli-program.ts`, `src/analyser.ts`, `src/types.ts`)
- **`check-ignore` semantics tightened** - explicit file checks no longer apply `.gitignore` rules that `analyse <file>` would bypass, while files under built-in ignored parent directories (for example `dist/generated.ts`) report the same default-ignore verdict that a directory scan would apply. (`src/discovery.ts`)
- **Sensitive-data: PHI + GCP service-account detection** - two new rules take the catalogue to 120: `sensitive-data.phi-pattern` flags PHI identifiers (Medicare Beneficiary Identifiers and labelled medical-record numbers) and `sensitive-data.gcp-service-account-key` flags GCP service-account key files (`"type": "service_account"` alongside a private key). Both route through the existing redaction contract, so no renderer (text/json/sarif/github/markdown/html) ever shows the raw value - only a redacted preview. Vendor secrets stay grouped under `sensitive-data.api-key-pattern` (no provider-specific rule split). (M26; `src/sensitive-data-rules.ts`, `src/rules.ts`)
- **Sensitive-data false-positive and profile fixes** - GCP service-account metadata now requires an actual `private_key` field or PEM private-key marker, not just `private_key_id`, before emitting the high-severity key-file finding. The strict profile's 24-character high-entropy threshold is now reachable because the detector enumerates candidates at the configured floor instead of hardcoding 32 characters first. (`src/sensitive-data-rules.ts`, `src/config.ts`, `src/profiles.ts`)
- **Dashboard secret redaction proof** - the live dashboard `/scan` HTML path now has a regression test proving sensitive-data findings render only redacted previews and do not include the raw synthetic credential URL or password fragment. No dashboard wire-format change. (`src/cli-surfaces.test.ts`)
- **Mission-first documentation + governance ADRs** - README, `docs/`, `.goat-flow/architecture.md`, and the `CLAUDE.md`/`AGENTS.md` headers now lead with gruff's purpose as a coding-agent hook: legible enough to verify, secure where the reviewer's eye slips, tested for real behaviour over low-signal ceremony. New `docs/philosophy.md` (the why) and `docs/agent-hook.md` (wiring it as a forcing function on agent output). ADR-005 records the mission; ADR-006 records that severity is ordering, not a gate (one severity + one value per rubric, no "tolerate N" gating). The npm description and HTML report masthead are reframed to match. (`README.md`, `docs/philosophy.md`, `docs/agent-hook.md`, `.goat-flow/decisions/ADR-005-optimise-for-reviewer-of-ai-generated-code.md`, `ADR-006-agents-fix-everything-severity-is-not-a-gate.md`)
- **Rubric calibration pass** - naming, test-quality, maintainability, and score/reporting rules now recognise stable reviewable-code conventions instead of forcing noisy rewrites: semantic digits in IDs, serialized/interface boolean names via `allowlists.acceptedBooleanNames`, comparator `(a, b)` parameters, fixture/invariant test sweeps, small cardinality assertions, documented empty test doubles, rationale-backed double casts, and prose-like comments that are not disabled code. Complexity and size score math now clusters overlapping root-cause findings once per function symbol while preserving each detailed finding and the `gruff.analysis.v2` field shape. (M06 / cross-port M14 policy, ADR-009; `src/class-rules.ts`, `src/naming-pushers.ts`, `src/test-block-rules.ts`, `src/blocks.ts`, `src/safety-rules.ts`, `src/findings-helpers.ts`, `src/scoring.ts`, `src/report-renderers.ts`)
- **Rule precision follow-ups** - DTO/interface fields and SCREAMING_SNAKE constants no longer hide same-surface local casing drift, semicolonless disabled calls are detected without reclassifying prose headings, conditional assertions inside type guards stay visible to `test-quality.conditional-logic`, and comments naming the changed-region CLI flags no longer trip `docs.stale-comment`. Synthetic test names are escaped before embedding in generated fixture source. ## v0.2.0 - 2026-05-28

Cross-format Pillars table, per-command gating defaults, JSON schema bumps (`v1` → `v2`), exported-doc rule split, a rule-precision sweep, config schema-versioning, and a code-review sweep against PR #4 feedback. Cut as a pre-1.0 minor bump because the cumulative rule-emission changes (new exported-doc surface, tightened naming/test-quality exemptions, schemaVersion requirement) materially shift findings for downstream consumers.

- **Per-command gating + schemaVersion contract** - `analyse` and `summary` default `--fail-on` flips from `error` to `advisory`; CI gates using the defaults go from "fail on errors only" to "fail on anything." New `minimumSeverity:` block in `.gruff-ts.yaml` pins per-command thresholds (`analyse / summary / report`) with precedence CLI flag > config > binary default; `dashboard` is rejected as a key because it has no `--fail-on` flag. `.gruff-ts.yaml` now requires `schemaVersion: gruff-ts.config.v0.1` at the top - pre-1.0 hard break, no transitional shim. Run `npx gruff-ts init --force` to migrate; the regenerated config preserves `paths.ignore` and `minimumSeverity`. (ADR-004, `src/config.ts`, `src/cli-program.ts`)
- **Cross-format Pillars table** - Canonical 7-column table (`Pillar | Grade | Score | Findings | Advisory | Warning | Error`) renders byte-aligned across `text`, `json`, `html`, and `markdown`, sorted `findings DESC` then `pillar ASC`. Clean pillars render as `A/100` rows so the column layout stays stable run-to-run; cross-port consumers can diff byte-for-byte. (`src/pillar-summary.ts`, `src/report-renderers.ts`, `src/report-html.ts`)
- **JSON schema bumps `v1` → `v2`** - `summary --format=json` emits `gruff.summary.v2`; the flat `{pillar, count}` per-pillar array is replaced with a richer shape carrying `grade`, `score`, `penalty`, `applicable`, `findings`, `advisory`, `warning`, `error`. `analyse` / `report --format=json` emit `gruff.analysis.v2`; `score.pillars[]` entries gain a `penalty: number` field, and the SARIF `runs[0].properties.gruffSchemaVersion` plus the JSON `schemaVersion` tag move in lockstep. Downstream consumers must gate on the `schemaVersion` field before decoding.
- **Public-API doc gate** - `docs.missing-function-doc` (advisory) is split into `docs.missing-exported-function-doc` (**warning**) and `docs.missing-internal-function-doc` (advisory). The warning variant fires on `export function`, `export const f = () => ...`, `export default function`, and locally-declared functions re-exported via `export { foo }` or `export default foo`; `export { foo } from "./other"` re-export-from clauses are correctly skipped via negative lookahead so a same-named local stays internal. Class methods of exported classes are intentionally treated as internal (advisory) by this release; enclosing-class scope tracking is deferred. Any `.gruff-ts.yaml` override targeting the old rule ID must be updated. (M04, `src/blocks.ts`, `src/doc-rules.ts`)
- **Summary readability + rule explain mode** - Per-severity grade breakdown under the composite (`Errors: A (0)`, `Warnings: D (276)`, `Advisory: F (1367)`) tells you whether an F composite is driven by errors or by a long tail of advisories; three grade pills in HTML. `summary` Top-N rule rows now show per-severity split and one-line descriptions: `- <ruleId>: <total> (<err> err / <warn> warn / <adv> adv) - <description>`; a `Tip:` line points at `summary --top=20` when `analyse` produces 50+ findings. `gruff-ts list-rules <ruleId>` accepts a positional argument and prints per-rule detail (text or JSON) with `Config keys:`, `Options:`, and `Allowlists:` blocks. Every tunable rule's `remediation` text now names its override knob (`rules.<id>.threshold`, `rules.<id>.severity`, allowlist keys) so the configuration surface is one greppable string away from any finding. (M05-M08)
