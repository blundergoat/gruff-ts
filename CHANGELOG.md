# Changelog

## v0.5.0 - 2026-07-12

- **Labeled data-driven test loops opt out of loop-in-test** - `test-quality.loop-in-test` now stays quiet when every assertion in a for..of loop carries a template message naming a loop-bound identifier (for example an assertion message interpolating `row.name`), because such loops keep a failing row identifiable even when the case table is built dynamically. The finding drops to medium confidence, and its message and remediation acknowledge parametrized tests: "Test contains loop logic that hides which iteration failed" / "Add a per-case message to looped assertions, or use a fixture table or separate named cases." Fixture-table suppression, while-loop reporting, and finding anchors are unchanged. Additionally, control-flow segments now find the loop body past the header's balanced parentheses, so destructured bindings (`for (const { name } of rows)`) and object-literal header arguments (`Object.entries({ ... })`) are analysed instead of silently skipped: destructured fixture tables and labeled loops correctly opt out, previously invisible destructured loops that hide their failing case now report, and a trailing bare `void identifier` lint-pacifier no longer disqualifies a fixture table. (`src/test-block-rules.ts`, `src/rules.ts`, `docs/rules.md`)
- **Acronym-case findings compare only casings the author chose** - `naming.acronym-case` no longer counts SCREAMING_SNAKE constants or all-lower names, whose conventions fix the acronym's case, so the standard TypeScript mix of `RAW_HTML_BLOCK_TAGS` beside `startsHtmlBlock` is quiet and no acronym has to be renamed out of a constant to satisfy the rule. Chosen-case drift still reports file-wide: `parsedHtml` beside `rawHTML` fires exactly as before. Compatibility: findings whose only upper-case evidence was a screaming constant disappear; where a chosen-case pair remains, the anchored second occurrence can shift, churning that finding's fingerprint and `stableIdentity` once. (`src/class-rules.ts`)
- **Child-process findings grade severity from their own evidence** - `security.process-exec` keeps warning severity only when a shell-enabled call takes a dynamic command (`template`, `parameter`, `member`, `local-builder`, `unknown` sources). A fixed command with the shell disabled reports as advisory with a message that names what would make it dangerous ("revisit if the command or its arguments start deriving from user input or a shell gets enabled"); every other combination is advisory with the existing review prompt. Metadata, anchors, fingerprints, and baseline matching are unchanged; the `stableIdentity` of fixed-vector shell-disabled findings intentionally churns once because their message changed and the rule emits no symbol (ADR-018). `--fail-on warning` consumers see fewer process-exec failures by design. (`src/line-rules.ts`, `src/rules.ts`, `docs/rules.md`)
- **The analyzer passes its own zero-finding self-scan again** - the 0.5.0-era parameter splitter in `src/findings-helpers.ts` is decomposed into a quote-state step, a nesting step, and a top-level predicate (behavior-identical, verified by the full suite), and the framework-redirect import walk in `src/security-flow-rules.ts` extracts its module gate and alias collector, clearing the complexity and context-doc findings the CI `analyse . --fail-on=advisory` gate had been reporting on the analyzer's own source. (`src/findings-helpers.ts`, `src/security-flow-rules.ts`)
- **Fixture-purpose findings are clearable by the fix their message names** - a purpose comment directly above (or on the line of) a large fixture now clears `docs.fixture-purpose-missing` when it is either the documented vocabulary or a substantive explanation of eight or more words, so a genuine purpose sentence no longer loses to a hidden keyword list. Stacked `//` headers are read as one comment (the shared `combinedContextLineComment` moved to `src/comment-scanner.ts`), matching the context-doc rules, and `docs.magic-threshold-without-rationale` reads the joined run for its leading-rationale check the same way. Test-setup candidates now say what they detected ("builds a large fixture setup") and each remediation names the accepted comment position. Anchors, fingerprints, and `stableIdentity` are unchanged for findings that still fire; template and generated candidates keep anchoring at the fixture line, test-setup candidates at the test declaration the comment belongs above. (`src/fixture-purpose-rules.ts`, `src/comment-scanner.ts`, `src/comment-rules.ts`)
- **Task-marker findings require a real marker, not a mention** - `docs.todo-without-tracking` now fires only when TODO/FIXME/HACK/XXX introduces a comment body line followed by a marker delimiter (`:`, `(`, `-`, whitespace, or end of line). Prose that mentions marker words mid-sentence, in quotes, or in backticks stays quiet, as do markers shown inside fenced doc-comment examples, so documenting a placeholder-detection feature no longer trips the rule. Conventional markers (including lowercase forms and bare `// TODO`) and the tracked-reference exemptions are unchanged. (`src/comment-rules.ts`)
- **Documentation and transport conventions no longer inflate naming/size debt** - `size.file-length` now counts substantive nonblank, non-comment lines while retaining its 750 default, metadata keys, and finding identity. Exact case-insensitive `allowlists.acceptedClassFilePairs` and `allowlists.acceptedCasingPairs` preserve feature-file/class-role conventions and same-contract wire aliases without weakening unlisted findings. `docs.missing-why-for-complex-code` evaluates contiguous leading `//` runs as one comment and recognises natural causal phrases such as `due to`, `so that`, `required by`, and `compatibility`; the public rules guide lists the accepted vocabulary. (`src/analyser.ts`, `src/class-rules.ts`, `src/comment-rules.ts`, `src/context-doc-rules.ts`)
- **Release CI is read-only and spans supported Node lines** - repository automation now grants only `contents: read` and runs dependency audit, TypeScript checks, unit tests, and the zero-finding self-scan on Node 22, 24, and 26. The coordinated agent instructions also recognize `typescript` as the approved syntax-only runtime parser alongside `commander` and `tsx`, preventing future maintenance from accidentally demoting a shipped dependency. (`.github/workflows/ci.yml`, `CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md`)
- **Release documentation matches the executable package** - public and maintainer docs now list all eleven commands, exactly 120 rules, Node.js 22+ with release coverage on 22/24/26, the distinct `commander`/`tsx`/`typescript` runtime roles, current schema strings, and the actual npm file surface. JSON keeps canonical `file` plus legacy `filePath`; the v0.3.1 one-release removal promise is replaced by the coordinated family JSON-unification timeline, with no port-local key removal. (`README.md`, `SECURITY.md`, `docs/releasing.md`, `.goat-flow/architecture.md`, `.goat-flow/code-map.md`, `src/report-renderers.ts`)
- **Published tarballs get an installed-user smoke gate** - the release check now packs into isolation, rejects test, fixture, maintainer, agent, and workflow files, installs the tarball in a fresh project, and runs its exposed `gruff-ts` binary against a generated known finding. It verifies JSON output and the documented finding exit code without importing files from the development checkout. (`scripts/pack-smoke.sh`)
- **Release facts have executable drift guards** - the catalogue suite pins exactly 120 descriptors, and a repeated full-pipeline scan validates each `run.generatedAt` timestamp before removing only that volatile field and requiring byte-identical normalized reports plus identical finding order and fingerprints. (`src/rule-catalogue.test.ts`, `src/release-truth.test.ts`)
- **Generated configs share one abbreviation vocabulary** - `gruff-ts init` now seeds the family 16-entry `acceptedAbbreviations` list, dropping callback-specific `cb` and `fn`, and explains how replacing the list changes naming findings before users edit the generated YAML. (`src/init-config.ts`)
- **GitHub Actions write-permission coverage follows the current scope table** - `security.github-actions-broad-permissions` now reports explicit writes for artifact metadata, attestations, code quality, discussions, OIDC identity tokens, and Pages, naming the granted scope in each finding. Existing scopes and `write-all` remain covered; `models` and `vulnerability-alerts` stay quiet because GitHub documents them as read-or-none, and legacy `repository-projects` coverage remains for Enterprise workflows. (`src/github-actions-rules.ts`)
- **Naming findings distinguish local edits from contract decisions** - boolean-prefix findings now mark local and parameter renames as `remediationAction: APPLY`; interface and named type-literal fields use `CONFIGURE` with `configurationKey: allowlists.acceptedBooleanNames` and explain the complete replacement-list or serialization-boundary options. Exact configured contract names remain type-gated, vague booleans still report, and non-boolean fields stay outside the rule. Class/file mismatch now reports only a named mismatched class that is the module's sole supported public declaration; public interface/type/enum/function/default/re-export siblings make feature modules quiet, while named default and bottom-re-export sole classes remain covered. Retained `PaymentController` identity is unchanged and gains `candidatePrimaryExport` plus sorted `publicExports` metadata. (`src/naming-pushers.ts`, `src/public-exports.ts`, `src/class-rules.ts`)
- **Casing consistency follows declaration and lexical owners** - `naming.inconsistent-casing` now compares variants within one module, function, interface, or named type-literal owner. A raw DTO field such as `note_id` and a normalized UI model field such as `noteId` no longer conflict when they live in separate contracts, while drift inside one function or contract still reports; same-name interface declaration blocks in one lexical scope remain one merged owner. Findings add deterministic owner id/kind/name metadata without changing retained rule/file/line/symbol identities or fingerprints. `naming.acronym-case` remains file-wide but now compares only chosen casings; see its own entry above. (`src/parsed-script.ts`, `src/class-rules.ts`)
- **Complexity follows TypeScript control flow instead of punctuation** - cyclomatic complexity now starts at one and counts `if`, loop, `catch`, non-default `case`, ternary, `&&`, and `||` syntax nodes once; `switch`/`default`, `??`, optional chains, non-null assertions, object literals, and ordinary braces add no decisions. Cognitive complexity adds only nested `if`, loop, `switch`, `catch`, and ternary depth, with peer-depth `else if` branches and non-stacking cases. Block findings and `docs.missing-why-for-complex-code` share the same result from the existing one-parse-per-script boundary, nested reported callables are measured separately, and unreported anonymous callbacks remain owned by their nearest reported function. Complexity metadata keeps `complexity`/`threshold` and adds a fixed per-kind `breakdown`; retained finding anchors, fingerprints, stable identities, thresholds, severities, and score clustering are unchanged. (`src/complexity-metrics.ts`, `src/blocks.ts`, `src/context-doc-rules.ts`)
- **Markdown reports escape repository-controlled structure** - finding rule labels, file paths, and correlated-complexity symbols now use inline-code fences longer than any backtick run in their content. Finding messages collapse line breaks, encode HTML delimiters, and escape Markdown controls, preventing analyzed repositories from injecting headings, links, emphasis, HTML-looking blocks, or broken code spans into pull-request comments. Ordinary rows and the seven-column Pillars table keep their readable layout; JSON, SARIF, GitHub, HTML, and text output are unchanged. (`src/report-renderers.ts`)
- **Filtered scans cannot record project history** - `analyse` now rejects `--history-file` with `--diff`, `--since`, or `--changed-ranges`, and `summary` rejects it with `--diff`. Invalid combinations exit `2` before analysis, report output, or history writes; normal full scans still append history, and both command help surfaces state the full-scan-only contract. (`src/cli-program.ts`)
- **Short secret previews no longer expose credential characters** - values below 24 characters now show a full mask and length, while values of at least 24 characters retain only their first and last four characters for reviewer triage. Fingerprints and `gruff.baseline.v1` matching are unchanged, but message-derived analysis and hook identities intentionally churn for affected findings: old hook baseline entries resurface once for fail-safe re-review (ADR-017). (`src/sensitive-data-rules.ts`)
- **Open-redirect findings require a recognized response or navigation sink** - local functions named `redirect` and arbitrary router methods such as `myRouter.redirect(...)` no longer produce security findings by name alone. Same-line and cross-line analysis still reports tainted input reaching `res.redirect`, `reply.redirect`, `response.redirect`, browser location assign/replace calls, or location href assignments. (`src/security-flow-rules.ts`)
- **Quoted environment-style secrets retain embedded hash characters** - hardcoded secret assignments wrapped in matching single, double, or backtick quotes are now evaluated using the complete quoted value, so an embedded `#` cannot truncate a real credential below the detection threshold. Unquoted values still stop at `#`, preserving `.env` comment behavior and the scanner's existing conservative handling of YAML, INI, and npmrc inputs. (`src/sensitive-data-rules.ts`)
- **Shared AST function discovery (one parse per script)** - each analysed script is parsed exactly once, and that single result now feeds parse diagnostics, security-flow analysis, block-level function discovery, and docblock export detection. Discovery is syntax-tree based: generic declarations, multi-line signatures, and parenless single-argument arrows are now analysed by size, complexity, naming, and documentation rules (24 previously invisible functions surfaced in gruff's own source and were fixed forward), while every previously discovered block keeps its exact anchor and fingerprint (verified block-for-block across the repository). `size.parameter-count` counts actual AST parameters, so commas inside generics, tuples, and defaults no longer inflate it; docblock rules cover `export async function` and can no longer be suppressed by prose containing the word `export`; and a bare `return (...) => ...` statement no longer masquerades as a callable named `return`. Accessors and `export default function` docblock coverage stay excluded pending a deliberate policy decision. (`src/parsed-script.ts`, `src/blocks.ts`, `src/analyser.ts`, `src/source-text.ts`, `src/security-flow-rules.ts`, `src/doc-rules.ts`, `src/findings-helpers.ts`, `src/baseline.ts`)
- **Config validation fails loudly instead of silently no-opping** - unknown rule ids under `rules:` are rejected at load time (matching the existing profile behavior); non-boolean `enabled` values such as YAML 1.2 strings `no`/`off`/`yes`/`on` fail naming the accepted forms `true`/`false`; and `rules.<id>.options` entries are validated against each rule's declared option keys, rejecting unknown keys (naming the accepted set) and non-numeric values. Compatibility tightening: configs that previously relied on silently dropped entries now fail with exit `2` and a concise message. (`src/config.ts`, `src/profiles.ts`)
- **Rule severity overrides apply to every scanner family** - `rules.<ruleId>.severity` now applies through one central post-creation pass, so the thirteen scanner modules that previously hardcoded descriptor literals (test-block, safety, project-config, comment, class, doc, naming, dead-code, security-flow, context-doc, fixture-purpose, static-analysis-redundant, and github-actions rules) honor configured severity in every report surface and in `--fail-on`. Fingerprints are severity-free, so existing baselines are unaffected. (`src/findings-helpers.ts`, `src/analyser.ts`)
- **Invalid CLI option values fail fast** - constrained values are validated at parse time as usage errors naming the accepted set: `analyse --format/--fail-on/--changed-scope`, `report --format/--fail-on`, and `summary --fail-on` no longer fall back silently (an invalid `report --fail-on` previously even landed on the `advisory` fallback instead of report's documented `none` default). `dashboard` accepts the cross-analyzer `--scan-timeout` flag with honest help text, and a regression test pins that a bare directory operand scans its whole subtree. This is a compatibility tightening for callers that relied on silent fallbacks. (`src/cli-program.ts`)
- **File-scoped parse diagnostics and hook diagnostics reporting** - parse/read diagnostics now follow one file-scoped policy on both surfaces: full scans keep every diagnostic, `--diff`/`--since` runs keep only diagnostics from changed target files, and `--changed-ranges` keeps every diagnostic of each requested file (never range-filtered). This intentionally loosens diff/since `analyse` runs: a pre-existing broken context file no longer fails a clean diff (full scans still exit `2`). The `gruff.hook.v1` envelope gains an additive `diagnostics` array (`{ type, message, file, line }`) plus a `supports.diagnostics` capability advertising the new explicit consumer request flag `--fail-on-diagnostics`; default hook exits stay `0` with diagnostics in-band, and fatal analysis failures keep operational-error exit `2`. (`src/changed-regions.ts`, `src/analyser.ts`, `src/hook-contract.ts`, `src/cli-program.ts`, `docs/agent-hook.md`)
- **Diff scoping works from nested directories** - `--diff`/`--since` runs read git diffs in relative-path mode, so changed-region findings match whether the scan runs from the repository root or a nested package directory, and a nested run can no longer match sibling-package files. Root-run diffs are byte-identical to the previous behavior; display paths are unchanged. (`src/changed-regions.ts`)
- **Same-line secrets stay distinct findings** - two different sensitive values on one line no longer collapse into one finding: sensitive-data scanners with match offsets populate `column` (also emitted as SARIF `startColumn`), and report dedupe discriminates same-line occurrences by column (ADR-017). Fingerprint values and `gruff.baseline.v1` matching are unchanged; a v1 baseline still matches equal-fingerprint same-line findings as one identity until the count-based `gruff.baseline.v2` lands with the coordinated cross-analyzer schema release. (`src/sensitive-data-rules.ts`, `src/baseline.ts`, `src/findings.ts`, `src/text-scans.ts`)



## v0.4.0 - 2026-06-11

- **Circular imports group by SCC** - `design.circular-import` reports one finding per strongly connected component (member list in `metadata.files`); circular-import fingerprints and hook identities intentionally churn (ADR-015). OpenUI dropped from 108 findings to 3.
- **Cycles stay visible in scoped scans** - narrow path scans build root graph context for the circular rule only, and changed-region and hook runs keep a cycle when any member file changed.
- **Scan-surface notes** - reports gain an additive `notes` field: `no-analysable-files` for paths with nothing analysable, `bounded-deep-scan` for huge files that keep text rules but skip deep passes. Notes name their file; diagnostics still own exit 2.
- **Generated-source policy** - explicit generation markers (`@generated`, `DO NOT EDIT`, ...) suppress documentation and naming findings only; every other pillar still runs.
- **Real TypeScript parse diagnostics** - the TypeScript syntax parser replaces the delimiter heuristic, so valid TSX no longer false-positives and real syntax errors keep exit 2.
- **Sensitive-data precision** - exempts word-segment identifiers, character-set alphabets, code-expression env values, Luhn digit runs without card vocabulary, and explicit fake markers (`EXAMPLE`, `REDACTED`, ...); real secrets still flag.
- **Security and test-quality tuning** - `security.sql-concatenation` covers `prepare(...)`, validation-only publish gates stop flagging `security.risky-lifecycle-script`, `security.process-exec` carries `callName`/`argumentSource`/`shellEnabled` hints, and static-import test sentinels downgrade to review guidance.
- **`dead-code.unused-private-method`** - bare `this.method` references count as usage; unrelated properties sharing the name no longer mask an unused private method.
- **Execution-level rule gating** - rules disabled by config or profile now skip their scanner passes instead of filtering findings afterwards, and the comment-quality gate no longer silently disables `docs.fixture-purpose-missing`.
- **Hook efficiency** - changed-region hook runs reuse one analysis pass; the diff/since new-only replay stays a second pass and materializes every SCC member, so pre-existing cycles are not reported as new. vscode-scale repos still need the minimal profile.

## v0.3.2 - 2026-06-09

- **Agent-hook contract v1** - adds `gruff-ts hook` and `gruff-ts hook --capabilities --format=json`, advertising `gruff.hook.v1` with `flagOrder:"any"`. Hook JSON uses the cross-analyzer contract fields (`file`, `scope`, `suppressed.count`, `ignored.paths`, `config.error`) with non-null remediation, stable hook identities, and machine-readable threshold metadata. Hook mode exits `0` when analysis runs, omits file/project-scope findings under changed-region attribution, and uses stable identity for baseline/diff new-only filtering (`--diff unstaged` compares against the index, `suppressed.count` never double-counts a re-emitted finding, and distinct project-scope findings such as separate import cycles anchored to one file keep distinct identities so baselining one never suppresses another). Operational failures (missing/malformed baseline, `--diff`/`--since` outside a git repo) report in-band as `config.error` with exit `2` rather than crashing. The conformance tests cover capabilities, scopes/enums, remediation, threshold metadata, stable identity across line/value changes (including multiple same-rule findings in one file and distinct import cycles sharing an anchor file), baseline and diff new-only, operational-failure JSON, flag ordering, advisory exit, ignored paths, and config-error JSON. Existing `analyse` / `summary` / `report` schema versions and exit semantics are unchanged. (`src/hook-contract.ts`, `src/cli-program.ts`, `src/hook-contract.test.ts`)
- **Changed-region symbol scope drops inherited file-wide findings** - `--changed-scope symbol` now suppresses file-wide and file-aggregate findings when the changed range does not touch their anchor/span, so inherited debt such as `size.file-length` is counted in `suppressedCount` instead of reported on unrelated edits. Use `--changed-scope file` for CI workflows that intentionally want every finding from a touched file, including deletion-only edits. Full scans still report every file-wide finding. No severity, threshold, rule-id, or pillar change. (`src/changed-regions.ts`, `src/changed-region-scope.test.ts`, `src/changed-region-contract.test.ts`)
- **Threshold findings expose reviewable measurements** - `size.file-length`, `size.function-length`, `size.parameter-count`, `complexity.cyclomatic`, `complexity.cognitive`, `sensitive-data.high-entropy-string`, and `sensitive-data.hardcoded-env-value` now carry additive `measured`/`threshold` measurement metadata, and block-anchored findings carry `endLine` spans so hook output can attribute symbol-scope findings without message parsing. `size.file-length` also gets finding-level remediation from the descriptor text. Existing fingerprints stay stable. (`src/analyser.ts`, `src/blocks.ts`, `src/findings.ts`, `src/sensitive-data-rules.ts`)

## v0.3.1 - 2026-06-03

- **JSON finding path alias and stable identity** - `analyse --format=json` and `report --format=json` now emit canonical `findings[].file` alongside the existing `findings[].filePath`; `filePath` is deprecated and will be removed in the next release. Findings also carry `stableIdentity`, a line-insensitive 16-hex identity for external diff tooling. Existing `fingerprint` values, baselines, SARIF fingerprints, dashboard data, and in-memory `filePath` consumers are unchanged.
- **Test-quality static-analysis redundancy rule and low-signal retirements** - adds `test-quality.static-analysis-redundant-test`, an advisory rule for tests that mostly assert statically knowable code shape instead of behaviour (for example `typeof exportedFunction === "function"`, direct `instanceof` construction, or non-null assertions against visible non-nullable return declarations). Findings include static-proof metadata and keep runtime payload/callable assertions quiet. The low-signal `test-quality.missing-nearby-test` project-layout rule and `test-quality.setup-bloat` setup-size rule are removed from the catalogue and config defaults; stale config entries are ignored. (`src/test-block-rules.ts`, `src/project-rules.ts`, `src/rules.ts`)
- **Per-rule `severity:` overrides now apply to the descriptor-driven line rules** - the `security.*`, `modernisation.*`, and `waste.*` regex line checks (for example `security.new-function`, `security.eval-call`) emitted findings with a hardcoded severity, so a project's `rules.<id>.severity` override in `.gruff-ts.yaml` was silently ignored. `pushPatternCheckFindings` now resolves severity through `ruleSeverity`, like every other pillar; the descriptor severity stays the default. A project running a legitimate `new Function`/eval shape (such as a transpile-then-execute test loader) can set `security.new-function: { severity: warning }` to keep the finding visible without failing an `--fail-on error` gate. No default severity, schema, or `Finding` shape change. (`src/line-rules.ts`, `src/security-and-config.test.ts`)

## v0.3.0 - 2026-05-30

0.3.0 release. Changes since 0.2.0: three breaking rule removals (`complexity.npath`; `size.stylesheet-length` with CSS dropped from scanned file types; and the `design.god-function` composite), region-scoped incremental analysis, authoritative `paths.ignore` with a new `check-ignore` command, sensitive-data PHI/GCP detection, named config profiles with `extends:` inheritance, and a documentation reframe around gruff's purpose - governing AI-generated code so a human who did not write it can sign off on it.

- **BREAKING: removed `complexity.npath`** - the rule and its `approximateNpath` helper are deleted; the complexity pillar is now `cognitive` + `cyclomatic`. Its `2^(decision tokens)` model false-flagged flat switches and guard-chains (easy-to-verify code) and its remediation pushed agents to fragment legible dispatch, while `cognitive` already covers genuine complexity (ADR-005, ADR-006). The `docs.missing-why-for-complex-code` gate drops its npath term (now size/cyclomatic/cognitive/nesting). No schema change (`gruff.analysis.v2` unchanged), but `list-rules`, reports, and findings no longer include `complexity.npath`, and a stale `rules.complexity.npath.*` config block is silently ignored. (`src/rules.ts`, `src/blocks.ts`, `src/context-doc-rules.ts`)
- **BREAKING: removed `size.stylesheet-length` and dropped CSS from scanned file types** - `.css` files are no longer discovered or analysed, and the CSS-only `size.stylesheet-length` rule (with its `isCssPath` gate) is deleted; the `size` pillar drops to 3. The rule could only ever fire on `.css` files, so dropping CSS scanning left it dead - same shape as the npath removal. No schema change (`gruff.analysis.v2` unchanged), but `list-rules`, reports, and findings no longer include `size.stylesheet-length`, and a stale `rules.size.stylesheet-length.*` config block is silently ignored. (`src/discovery.ts`, `src/analyser.ts`, `src/rules.ts`, `.gruff-ts.yaml`)
- **BREAKING: removed the `design.god-function` composite** - the rule and its `pushGodFunctionFinding` emitter are deleted; the `design` pillar drops from 6 to 5 and the catalogue from 120 to 119 (still 11 pillars). It fired only when a function was both long (>45 lines) and complex (cyclomatic >10) - a synthetic restatement of the `size.function-length` + `complexity.*` findings already on that symbol, whose only honest score is neutral once ADR-009 clusters those findings into one penalty. `design.god-function` is dropped from `CORRELATED_COMPLEXITY_RULE_IDS` while `complexity.cognitive`, `complexity.cyclomatic`, and `size.function-length` stay, so a long-and-complex function still moves the grade once with every finding listed - P5 now rests on that clustering, not on a named composite. Family-wide retirement of the `design.god-*` composite (gruff-rs removed it first); the named god-function signal is the only loss. No schema change (`gruff.analysis.v2` unchanged), but `list-rules`, reports, and findings no longer include `design.god-function`, and a stale `rules.design.god-function.*` config block is silently ignored. (ADR-011, ADR-009; `src/rules.ts`, `src/blocks.ts`, `src/scoring.ts`, `src/report-renderers.ts`)
- **Named config profiles with `extends:` inheritance** - a `profile:` block (or `--profile` flag) selects a bundled rule set instead of enumerating every rule by hand. Three built-ins ship with the binary: `gruff.minimal` (security and sensitive-data only), `gruff.recommended` (every pillar at its defaults - byte-identical to a zero-config scan), and `gruff.strict` (every pillar with tightened size, complexity, and secret thresholds). The inline form extends a built-in name or a relative profile file and overrides individual rules or ignored paths, with deterministic child-wins flattening (per-rule fields merge; `ignoredPaths` arrays replace). Precedence: `--profile` flag > config `profile:` > the `extends:` chain > the default `recommended`; a top-level `rules:` entry still overrides the profile. Unknown built-in/file, `extends:` cycles, and rule ids outside the catalogue all error at load time - file paths only, no remote URLs or shell. New `list-profiles` command plus `--profile <name-or-path>` on `analyse`/`report`/`summary`/`dashboard`. Config-only: no `gruff.analysis.*`/`gruff.baseline.*` schema change. The zero-dependency YAML parser and value-narrowing helpers moved from `src/config.ts` to a new `src/config-parse.ts` so the config module stays legible. (ADR-010; `src/profiles.ts`, `src/config.ts`, `src/config-parse.ts`, `src/cli-program.ts`, `src/rule-list.ts`, `src/types.ts`)
- **Region-scoped incremental analysis** - lets a coding agent run gruff-ts as a hook on only the code it changed, not the whole repo, so it resolves findings in its own diff before a human reviews and a clean change is never blocked by pre-existing findings elsewhere. `--changed-scope <symbol|hunk>` narrows findings to changed code: `symbol` reports findings whose enclosing declaration changed, `hunk` only those on changed lines. Driven by `--changed-ranges "<start>-<end>,..."`, `--since <ref>`, or `--diff` (including `git diff | gruff-ts analyse --diff -`). JSON keeps the normal `findings` array and adds `suppressedCount` when region filtering is active, so a PR check can gate on "did this change introduce findings?" without a baseline file. (`src/changed-regions.ts`, `src/analyser.ts`, `src/cli-program.ts`, `src/types.ts`)
- **Region-scoped analysis hardening** - diff-scoped runs now keep full project context for cross-file rules before filtering emitted findings, so central tests/import graphs remain visible while unchanged findings are still suppressed. Piped unified diffs track actual added target lines instead of hunk-header spans, deletion-only hunks no longer create target ranges, base-ref diffs no longer pull in unrelated untracked files, custom refs are passed after `--end-of-options`, file-wide findings stay visible when any hunk touches their file, and `export default class` bodies participate in symbol-scope matching. (`src/analyser.ts`, `src/changed-regions.ts`)
