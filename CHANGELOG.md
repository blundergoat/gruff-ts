# Changelog

## v0.6.0 - Unreleased

A coordinated family release on Node 22+ that unifies JSON, SARIF, baseline, hook, and scoring contracts across all five gruff ports, trims the catalogue from 120 to 81 rules across 11 pillars, enforces full `/** ... */` JSDoc contracts on non-test callables, and scales cleanly to 10,000+ file TypeScript monorepos. Upgrading from `0.5.x` changes every machine-readable contract at once; see [UPGRADING.md](UPGRADING.md) for the step-by-step migration and rollback path.

### Breaking changes

- **BREAKING: machine contracts move to family v3 and `gruff.hook.v2`** - `analyse` and `report --format=json` emit `gruff.analysis.v3`, and `summary --format=json` emits `gruff.summary.v3` (the same envelope without top-level `findings`, so `--top` affects text output only). Gate on `schemaVersion`, read `file` instead of `filePath`, read `score.composite.{score,grade}`, read `paths.details` instead of `paths.skipped`, and treat absent optional fields (`column`, `endLine`, `symbol`) as omitted rather than `null`; see the full field table in [Output Formats](docs/output-formats.md). `hook` moves to `gruff.hook.v2`, adding `run` and `suppressions` and ratifying exit codes `0`, `1` (explicit gate), and `2` (fatal). There is no deprecation window for this pre-1.0 family break.
- **BREAKING: baselines move to `gruff.baseline.v3` with line-free identities, and secrets can no longer be baselined** - Each baseline row stores a line-free SHA-256 identity (tool language, rule ID, project-relative path, and either `symbol#ordinal` or a message with digits normalised to `#`) plus an accepted count, so shifting lines no longer re-opens reviewed findings and same-named declarations stay distinct. SARIF `partialFingerprints.gruffFingerprint` uses the same identity, so existing code-scanning alerts close and reopen once on upgrade. Sensitive-data findings carry no baseline row and no SARIF `partialFingerprints`; suppress reviewed sample secrets with `sensitiveExclusions:` instead. `0.5` baselines fail closed with exit `2`; carry them forward with `gruff-ts analyse --migrate-baseline <old> --generate-baseline <new>`.
- **BREAKING: 40 low-precision rules are removed (ADR-021)** - Rules that were right less than half the time in the 0.6.0 precision measurement are deleted: `complexity.cognitive`, `design.deep-relative-import`, `docs.magic-threshold-without-rationale`, `docs.stale-comment`, `docs.useless-docblock`, `modernisation.loose-equality`, `modernisation.nullish-coalescing-candidate`, `modernisation.object-spread-candidate`, `modernisation.optional-chaining-candidate`, `modernisation.public-property`, `naming.acronym-case`, `naming.boolean-prefix`, `naming.generic-function`, `naming.generic-parameter`, `naming.hungarian-notation`, `naming.inconsistent-casing`, `naming.negative-boolean`, `security.floating-promise`, `security.github-actions-broad-permissions`, `security.insecure-random`, `security.process-exec`, `security.proto-access`, `security.risky-lifecycle-script`, `sensitive-data.hardcoded-env-value`, `sensitive-data.high-entropy-string`, nine test-quality rules (`conditional-logic`, `exception-type-only`, `magic-number-assertion`, `mock-only-test`, `no-assertions`, `no-throw-only-test`, `only-skip`, `sleep-in-test`, `snapshot-only-test`), and six waste rules (`commented-out-code`, `console-log`, `empty-function`, `redundant-boolean-cast`, `redundant-variable`, `unused-parameter`), along with their seven allowlist keys (`acceptedBooleanNames`, `acceptedCasingPairs`, `bannedGenericNames`, `booleanPrefixes`, `hungarianPrefixes`, `knownAcronyms`, `negativeBooleanAllowed`). Configs, `sensitiveExclusions:`, and `--include-rule`/`--exclude-rule` naming a retired ID fail with exit `2`. Run `gruff-ts migrate-config --config <old> --output <new>` to prune retired entries automatically while keeping surviving overrides. Baseline rows for retired rules still load and report as resolved. `docs.missing-why-for-complex-code` keeps a fixed cognitive-complexity trigger of 15, and ESLint `no-console`, `eqeqeq`, and `no-unused-vars` comments no longer suppress anything.
- **BREAKING: 12 rules are off by default** - `complexity.cyclomatic`, `docs.missing-invariant-doc`, `docs.missing-side-effect-doc`, `security.inner-html`, `security.open-redirect-candidate`, `security.path-traversal-candidate`, `security.unsafe-deserialization`, `sensitive-data.aws-access-key`, `sensitive-data.database-url-password`, `sensitive-data.jwt-token`, `waste.swallowed-catch`, and `waste.useless-return` now require `rules.<id>.enabled: true` (ADR-021; each fell short of its precision floor or relies on narrow keyword matching). Existing configs generated by an earlier `init` already set `enabled: true` and keep them on; `gruff.strict` no longer enables or tightens `complexity.cyclomatic`. Narrowing `--include-rule` to rules that are all disabled exits `2`.
- **BREAKING: every `sensitive-data.*` rule defaults to `warning`** - All eight surviving sensitive-data rules move from `error` to `warning` so heuristic matches stop forcing blanket ignores. `--fail-on=error` no longer fails on secret findings; use `--fail-on=warning` or set `severity: error` per rule in `.gruff-ts.yaml`.
- **BREAKING: per-command exit gates move from `minimumSeverity:` to `failOn:`, and config validation rejects unknown keys** - `minimumSeverity:` is now a single display-floor severity (`advisory`, `warning`, or `error`) that filters printed output without changing scores or exit codes; a 0.5 per-command map under `minimumSeverity:` exits `2` until renamed to `failOn:`. `allowlists.secretPreviews` is removed (reports use fixed category markers unconditionally), and any key inside `rules.<id>` outside `enabled`, `severity`, `threshold`, and `options` exits `2`. Run `gruff-ts migrate-config` to convert 0.5 configs.
- **BREAKING: normalized confidence-weighted scoring and `null` composites** - Each pillar scores as `floor + (100 - floor) / (1 + density / densityScale)` over evaluated script files, so duplicating a project keeps the same grade. Error weight rises from `8` to `12`, advisory weight drops from `1.5` to `1`, and findings weigh by rule confidence (`0.5` low, `0.75` medium, `1.0` high). Seven rules change confidence (`docs.missing-why-for-complex-code`, `docs.suppression-without-rationale`, `naming.identifier-quality` medium to low; `docs.todo-without-tracking`, `size.parameter-count`, `waste.any-type` high to medium; `security.sql-concatenation` high to low), and emitted findings always inherit their catalogue confidence (moving `docs.missing-exported-function-doc` and `docs.missing-internal-function-doc` from high to medium, and `size.function-length` from medium to high). `score.pillars[]` lists every rule-backed pillar with `applicable` and `grade`, and `score.composite.{score,grade}` return `null` (`Composite: n/a (nothing evaluated)`) when zero scripts were evaluated.
- **BREAKING: JSDoc tag rules require `/** ... */` contracts across non-test callables** - `docs.missing-param-tag` and `docs.missing-return-tag` enable `everyCallable` by default across arrow and function-expression constants, class and object methods, default and later exports, and private/nested functions on non-test source (skipping test files while keeping fixture directories checked). Both require `/** ... */` JSDoc blocks with described tags rather than `//` or `/* */` comments; `docs.missing-return-tag` requires described `@returns` on every checked callable including `void`, `Promise<void>`, `asserts`, `never`, and `undefined` (excluding constructors and setters). Undocumented public methods of exported classes report as `docs.missing-exported-function-doc` (`warning`), while private functions stay `docs.missing-internal-function-doc` (`advisory`). Set `everyCallable: false` on both rules to keep the earlier export-only scope.
- **BREAKING: `summary` defaults to `--fail-on none`, `report --no-baseline` is removed, and invalid inputs exit `2`** - `summary` now exits `0` unless `--fail-on` or `failOn.summary` is set. `report --no-baseline` exits `2` as an unknown option (`report` never applied baselines). Empty or malformed `--changed-ranges`, and missing, malformed, or 0.5 `--baseline` files, exit `2` with one fatal `changed-region` or `baseline-error` diagnostic and no findings instead of scanning everything or printing a stack trace.
- **BREAKING: `list-rules --format=json` uses the family rule record** - Each rule uses `id` (was `ruleId`), `defaultSeverity` (was `severity`), and a named `thresholds` map (was scalar `threshold`); `list-rules <id> --format=json` publishes the same shape under `rule`. Analysis findings keep `ruleId`.
- **BREAKING: default discovery uses the family fallback policy and tracking tokens move to config** - Non-VCS fallbacks defer to any governing `.gitignore` and match at any depth, committed control folders stay scannable, explicit file arguments bypass Git and fallback exclusions, and VCS internals remain blocked even under `--include-ignored`. Project-specific tracking references (such as ADR IDs or task paths) no longer count automatically; list regular expressions under `allowlists.trackingTokens` for `docs.todo-without-tracking`, `modernisation.ts-comment-without-rationale`, and `waste.swallowed-catch`.

### Added

- **`gruff-ts migrate-config` converts 0.5 configs end-to-end** - Renames per-command `minimumSeverity:` to `failOn:`, prunes all 40 retired rules, 7 retired allowlist keys, `allowlists.secretPreviews`, and retired `sensitiveExclusions:` entries (rewriting emptied YAML sections to `[]` or `{}`), logs each removal, and validates the migrated output with the 0.6 loader before writing to a separate file.
- **`analyse --migrate-baseline <old> --generate-baseline <new>`** - Re-identifies reviewed findings from a 0.5 baseline into a new `gruff.baseline.v3` file without touching the original, refusing same-file targets (including symlinks and hard links) and ambiguous multi-container 0.5 files. Generating at default `gruff-baseline.json` refuses to overwrite a non-v3 baseline unless `--force` is passed.
- **Reviewed `sensitiveExclusions:` config section** - Suppresses a reviewed sensitive-data finding by exact `rule`, project-relative `path`, optional `symbol`, and mandatory `reason`. Every exclusion is counted in `suppressions` and text output without ever printing secret text; value- or message-matching keys exit `2`. The bundled YAML parser now supports multi-line `- key: value` list items so `sensitiveExclusions:` works in YAML.
- **`test-quality.duplicate-test-body` enabled by default** - Flags groups of at least three tests of at least three statements in one lexical container with matching normalized bodies, recommending labelled table-driven tests; disable with `rules.test-quality.duplicate-test-body.enabled: false`.
- **Inline tool suppressions and duplicate `eval` merging** - Per-line ESLint (`no-eval`, `no-new-func`), Biome (`lint/security/noGlobalEval`, `lint/correctness/noUnusedImports`), and zizmor (`ignore[unpinned-uses]`, `ignore[dangerous-triggers]`) comments on the reported line or alone directly above it suppress the matching gruff finding, and an `eval` call flagged by both `security.eval-call` and `security.unsafe-deserialization` reports once as `security.eval-call`. Every removal is counted in `suppressions` (`inline` or `duplicate`) and preserved in SARIF.
- **Reviewed false-positive guidance on every medium- and low-confidence rule** - All 50 medium- and low-confidence rules publish `falsePositiveShapes` in `list-rules <id>` and `list-rules --format=json`; the 31 high-confidence rules omit the field.
- **Two-band size and complexity findings** - `size.*` and `complexity.*` findings below 1.5x their limit report as `advisory` (`metadata.limitBand: "lower"`) advising not to grow the unit; at 1.5x or above they keep their configured severity (`limitBand: "upper"`) and advise splitting or simplifying.
- **AWS `ASIA` session tokens detected** - `sensitive-data.aws-access-key` now flags temporary `ASIA` session keys alongside long-term `AKIA` keys.

### Changed

- **Large monorepos scan without hitting Node's 4 GB heap limit** - Full scans compute declaration spans per file, drop parsed ASTs outside changed-region targets, and store pre-extracted import statements instead of full file line arrays; `openclaw` (17,296 files) and `vscode` (12,867 files) complete with exit `0`.
- **Vendored, `dist`, and `.min.` files skipped by default** - `vendor`, `vendors`, `third_party`, `third-party`, `bower_components`, `dist` (at any depth and case), and `*.min.*` files are skipped even when a `.gitignore` is present, with reasons recorded in `paths.details`; `--include-ignored` or naming a file explicitly still scans them. `gruff-ts init` no longer pre-populates `generated` and `tmp` in `paths.ignore`.
- **Security and sensitive-data rules skip test, fixture, and example paths** - Files under `test`, `tests`, `__tests__`, `spec`, `testdata`, `fixtures`, or `examples` (any case) or named like a test (`*.test.*`, `*.spec.*`, `*_test.go`, `test_*.py`, `*_test.py`, `*Test.php`) are skipped by both pillars and recorded as counted `source: "built-in"` audit rows. **Trade-off:** a real secret or unsafe call committed under one of those paths is no longer reported. Twenty vendor-documented sample values (AWS example keys, jwt.io sample token, Google reCAPTCHA test site key, and 14 test card numbers) and stock local dev database credentials (`postgres:postgres`, `root:root`, `scott:tiger` on loopback or single-label hosts) also stay quiet.
- **Stricter, clearer documentation checks** - `docs.missing-param-tag` and `docs.stale-param-tag` list all missing or stale parameters in one finding; `docs.missing-exported-function-doc` and `docs.missing-internal-function-doc` name which parameters, return values, or throws need covering; `docs.missing-error-behavior-doc` requires an explicit `@throws` tag; file overviews and one-line section dividers (`// ----`) no longer count as a function's docblock; and `docs.suppression-without-rationale` and `modernisation.ts-comment-without-rationale` accept rationales in the `//` lines directly above the directive.
- **Line counts and callable measurements refined** - `size.file-length` measures JS/TS only (skipping JSON/YAML/TOML/XML), and code-line metrics (`size.function-length`, `size.file-length`, `design.large-module-concentration`, context-doc length) exclude blank, comment-only, and decorator-only lines. `size.function-length`, `size.parameter-count`, and `complexity.cyclomatic` now also measure object-literal `key: function` methods, member-assigned functions, `var` function expressions, and IIFEs (separately from their enclosing function), and `complexity.cyclomatic` counts a `switch` as one decision regardless of case count.
- **Clearer reporting and remediation** - `analyse` text prints the applied baseline line (`Baseline: ...; suppressed N findings`) and suppression totals (`Suppressed findings: N via ...`), `summary` prints suppression totals too, `score.evaluatedFiles`, `score.scoredPillars`, and per-file `penalty` appear in JSON, baseline JSON always includes zeroed movement counts on generate/migrate runs, baseline collisions report as a non-fatal `baseline-collision` diagnostic rather than hiding findings, and 11 line-pattern rules now include their remediation text in JSON while metric remediations stop advising raised thresholds.
- **Published tarball excludes `src/test-fixtures.ts`** - Test helper fixtures and synthetic credential strings no longer ship in the npm package.

### Fixed

- **TypeScript parser and rule precision** - `waste.unused-import` resolves named imports through the TypeScript AST and JS identifier boundaries so inline `type` modifiers and `$`-bearing bindings (`$`, `$state`, `events$`) no longer false-report. `docs.stale-param-tag` accepts destructured object and matching dotted property `@param` tags across all non-test `everyCallable` targets. `naming.short-variable` exempts `t` when typed as `TestContext` or inside test files, `docs.missing-why-for-complex-code` skips `it`/`test` callbacks and accepts constraint rationale (`must`, `never`, `only`, `instead`) when the comment adds information beyond the function name, and `design.package-bin-missing` downgrades unbuilt `dist/`/`build/`/`lib/` bins to `advisory` when `package.json` defines a `build` script.
- **Security, modernisation, and test-quality false positives** - `modernisation.readonly-property-candidate` reports only `private` fields assigned solely in their own constructor; `security.eval-call` skips fixed strings and static templates; `security.inner-html` skips static strings and templates; `security.javascript-url` skips equality comparisons; `security.weak-crypto` skips `createHmac("sha1", ...)`; `security.unsafe-deserialization` stops treating bytes read via Node `fs` as tainted input; `security.disabled-tls-verification` skips test assertion expectations; `security.github-actions-secrets-in-pr` checks `on:` for `pull_request_target`, skips `secrets.GITHUB_TOKEN`, and honours exact `github.event_name` guards; `security.url-dependency` anchors on the dependency entry rather than an `overrides` key; callback-local `req`/`request`/`ctx` parameters no longer taint enclosing values; `sensitive-data.aws-access-key` treats only 16-`X` bodies as masked; `sensitive-data.database-url-password` skips TypeScript template literal types; `docs.missing-side-effect-doc` ignores `RegExp.exec`; `waste.unreachable-code` recognises braced `case`/`default` labels; `waste.swallowed-catch` accepts explained empty catches and `waste.useless-return` skips a lone `return;` in `catch`; `void it(...)`/`void test(...)` callbacks are scanned as tests; and `test-quality.loop-in-test` recognises wrapped per-case messages and loop-derived expected values.
- **Baseline ordinals and `#` symbols** - Baseline ordinals now count every same-named declaration in the file and resolve leading-comment docblock findings (`docs.missing-param-tag`, `docs.missing-return-tag`, `docs.stale-param-tag`) to their following declaration span, so adding or editing comments never shifts a namesake's review. Findings whose symbol contains `#` (such as test titles citing issue numbers) no longer crash the run; they report without a baseline identity.
- **CLI paths, nested templates, hook duplicates, and installed launcher** - Relative target, `--config`, `--baseline`, `--generate-baseline`, and `--migrate-baseline` paths resolve from the launch directory rather than the project root, and config errors print the path as typed instead of a host-absolute path. Only real config-load errors emit a `config-error` envelope (not flag conflicts). Nested `${...}` template literals no longer desynchronise masking, `hook --diff` keeps newly added duplicate findings visible instead of hiding every matching line, and the installed `@blundergoat/gruff-ts` binary locates hoisted `tsx` from any working directory.

## v0.5.0 - 2026-08-16

120 rules across 11 pillars on Node 22+. Every script rule now reads one shared syntax-only AST parse instead of walking lines, scoring changes shape, config and CLI validation fail instead of coercing, and the release gains gates that fail the build when a documented count or the scan surface drifts from the source.

**Analysis.** Complexity, naming, docblock, and redirect rules read the shared parse, so generic, multi-line, and parenless-arrow declarations are analysed for the first time and complexity findings carry a per-kind `breakdown`. Findings narrow to real evidence: name-only `redirect` helpers, lockfile integrity digests, and bodyless overload signatures stop reporting, while tainted input reaching a response sink and a credential in a `resolved` URL still do. A false-positive sweep took the analyser's own scan to zero findings, which CI now enforces.
**Scoring.** The composite averages all 11 rule-backed pillars and counts a clean pillar as 100 (ADR-019), so fixing a pillar's last finding cannot lower the score. It stays volume-sensitive and is not yet a cross-project grade: vulnerable nodejs-goof scores 77.9 against clean zod at 18.8.
**Guardrails and release.** The Claude, Codex, and Copilot agent surfaces move to goat-flow 1.15.1, and three deny-hook bypasses are fixed locally ahead of the upstream template. Packaging is gated by a tarball smoke test that installs the pack fresh and runs the binary, with read-only CI across Node 22, 24, and 26.
**Needs action before upgrading.** Outside-root scans emit absolute paths, so regenerate any baseline built from a different working directory. `cb` and `fn` now trigger `naming.short-variable` unless listed in `allowlists.acceptedAbbreviations`. `size.file-length` is an error at 1000 substantive lines, which moves `--fail-on` exit codes.

- **BREAKING: External finding paths** - outside-root scans emit absolute paths; regenerate baselines made from a different working directory.
- **BREAKING: Family abbreviations** - `cb`/`fn` now trigger `naming.short-variable`; add them to `allowlists.acceptedAbbreviations` to retain them.
- **file-length raised to error at 1000 (family ratification)** - only the threshold and severity moved; `--fail-on` consumers see exit-code changes.
- **Shared AST discovery (one parse per script)** - generics, multi-line, and parenless arrows analysed; anchors and fingerprints preserved.
- **Complexity follows control flow** - syntax nodes drive cyclomatic/cognitive; findings gain a `breakdown`; thresholds and identities unchanged.
- **Docblock rules require the shared parse** - AST signatures only, so paren types cannot fake stale @param tags; bounded files skip the pack.
- **Composite counts clean pillars as 100** - the mean spans all 11 pillars; fixing a pillar's last finding cannot lower it (ADR-019).
- **Known scoring limitation** - composite scores remain volume-sensitive: vulnerable nodejs-goof scores 77.9 (C), NodeGoat 52.2 and clean zod 18.8.
- **Casing consistency follows owners** - variants compare within one module/function/interface owner; DTO vs UI fields no longer conflict.
- **Re-opened namespaces are one contract** - the merge scope keys on the namespace path, so casing drift between `namespace Api` blocks now reports.
- **Open-redirect needs a real sink** - name-only `redirect` helpers stay quiet; tainted input to response/location sinks still reports.
- **React Router redirects are open-redirect sinks** - `react-router` and `react-router-dom` join next/navigation and remix; local helpers stay quiet.

- **Quoted env secrets keep embedded hashes** - quoted values read whole so `#` cannot truncate a credential; unquoted still stop at `#`.
- **Same-line secrets stay distinct** - column discriminates same-line findings and ships in the hook payload (ADR-017); fingerprints unchanged.
- **Markdown reports escape repo text** - fenced labels/paths and escaped messages block injection into PR comments. (`src/report-renderers.ts`)
- **Actions write-permission scopes match GitHub's 2026-07-12 table** - `discussions` and `pages` count as write; `id-token` mints tokens, not writes.
- **Config validation fails loudly** - unknown rules, non-boolean enabled, bad option keys exit 2 naming accepted forms; compat tightening.
- **Invalid CLI values fail fast** - format/fail-on/changed-scope validated at parse as usage errors; compat tightening. (`src/cli-program.ts`)
- **Severity overrides reach every scanner** - one central pass applies rules.<id>.severity everywhere; fingerprints stay severity-free.
- **Filtered scans cannot record history** - `--history-file` with diff/since/ranges exits 2 before any write; full scans still append.
- **Diff scoping works from nested directories** - relative-path git diffs; nested runs cannot match siblings; root runs byte-identical.
- **Parser errors collapse per file** - reports retain the first message plus raw count; angular drops 1,854 diagnostics to 476 affected files.
- **Non-text scripts skip parsing** - invalid UTF-8 or NUL-bearing files produce a non-fatal `non-text-file` note instead of a parse error.
- **Guardrail hooks deliberately diverge from the goat-flow template** - `install`/`hooks sync` reverts them; re-apply after any upgrade.
- **Naming and size false positives cut** - aliased class exports, parameter defaults, short locals, acronym pairs, and bodyless signatures go quiet.
- **Docs and test false positives cut** - decorator comments, stacked fixture-purpose headers, quoted task markers, and labeled data loops stay quiet.

## v0.4.0 - 2026-06-11

- **Circular imports group by SCC** - `design.circular-import` reports one finding per strongly connected component (member list in `metadata.files`); circular-import fingerprints and hook identities intentionally churn (ADR-015). OpenUI dropped from 108 findings to 3.
- **Cycles stay visible in scoped scans** - narrow path scans build root graph context for the circular rule only, and changed-region and hook runs keep a cycle when any member file changed.
- **Scan-surface notes** - reports gain an additive `notes` field: `no-analysable-files` for paths with nothing analysable, `bounded-deep-scan` for huge files that keep text rules but skip deep passes. Notes name their file; diagnostics still own exit 2.
- **Generated-source policy** - explicit generation markers (`@generated`, `DO NOT EDIT`, ...) suppress documentation and naming findings only; every other pillar still runs.
- **Real TypeScript parse diagnostics** - the TypeScript syntax parser replaces the delimiter heuristic, so valid TSX no longer false-positives and real syntax errors keep exit 2.
- **Sensitive-data precision** - exempts word-segment identifiers, character-set alphabets, code-expression env values, Luhn digit runs without card vocabulary, and explicit fake markers (`EXAMPLE`, `REDACTED`, ...); real secrets still flag.
- **Security and test-quality tuning** - `security.sql-concatenation` covers `prepare(...)`, validation-only publish gates stop flagging `security.risky-lifecycle-script`, `security.process-exec` carries `callName`/`argumentSource`/`shellEnabled` hints, and static-import test sentinels downgrade to review guidance.
- **`dead-code.unused-private-method`** - bare `this.method` references count as usage; unrelated properties sharing the name no longer mask an unused private method.
- **Execution-level rule gating** - rules disabled by config or profile now skip their scanner passes instead of filtering findings afterwards, and the comment-quality gate no longer silently disables `docs.fixture-purpose-missing`.
- **Hook efficiency** - changed-region hook runs reuse one analysis pass; the diff/since new-only replay stays a second pass and materializes every SCC member, so pre-existing cycles are not reported as new. vscode-scale repos still need the minimal profile.

## v0.3.2 - 2026-06-09

- **Agent-hook contract v1** - adds `gruff-ts hook` and `gruff-ts hook --capabilities --format=json`, advertising `gruff.hook.v1` with `flagOrder:"any"`. Hook JSON uses the cross-analyser contract fields (`file`, `scope`, `suppressed.count`, `ignored.paths`, `config.error`) with non-null remediation, stable hook identities, and machine-readable threshold metadata. Hook mode exits `0` when analysis runs, omits file/project-scope findings under changed-region attribution, and uses stable identity for baseline/diff new-only filtering (`--diff unstaged` compares against the index, `suppressed.count` never double-counts a re-emitted finding, and distinct project-scope findings such as separate import cycles anchored to one file keep distinct identities so baselining one never suppresses another). Operational failures (missing/malformed baseline, `--diff`/`--since` outside a git repo) report in-band as `config.error` with exit `2` rather than crashing. The conformance tests cover capabilities, scopes/enums, remediation, threshold metadata, stable identity across line/value changes (including multiple same-rule findings in one file and distinct import cycles sharing an anchor file), baseline and diff new-only, operational-failure JSON, flag ordering, advisory exit, ignored paths, and config-error JSON. Existing `analyse` / `summary` / `report` schema versions and exit semantics are unchanged. (`src/hook-contract.ts`, `src/cli-program.ts`, `src/hook-contract.test.ts`)
- **Changed-region symbol scope drops inherited file-wide findings** - `--changed-scope symbol` now suppresses file-wide and file-aggregate findings when the changed range does not touch their anchor/span, so inherited debt such as `size.file-length` is counted in `suppressedCount` instead of reported on unrelated edits. Use `--changed-scope file` for CI workflows that intentionally want every finding from a touched file, including deletion-only edits. Full scans still report every file-wide finding. No severity, threshold, rule-id, or pillar change. (`src/changed-regions.ts`, `src/changed-region-scope.test.ts`, `src/changed-region-contract.test.ts`)
- **Threshold findings expose reviewable measurements** - `size.file-length`, `size.function-length`, `size.parameter-count`, `complexity.cyclomatic`, `complexity.cognitive`, `sensitive-data.high-entropy-string`, and `sensitive-data.hardcoded-env-value` now carry additive `measured`/`threshold` measurement metadata, and block-anchored findings carry `endLine` spans so hook output can attribute symbol-scope findings without message parsing. `size.file-length` also gets finding-level remediation from the descriptor text. Existing fingerprints stay stable. (`src/analyser.ts`, `src/blocks.ts`, `src/findings.ts`, `src/sensitive-data-rules.ts`)

## v0.3.1 - 2026-06-03

- **JSON finding path alias and stable identity** - `analyse --format=json` and `report --format=json` now emit canonical `findings[].file` alongside the existing `findings[].filePath`; `filePath` is deprecated and will be removed in the next release.
