# ADR-014: Scan Surface Notes And Generated Source Policy

**Status:** Implemented
**Date:** 2026-06-10
**Author(s):** Codex, user
**Ticket/Context:** 0.4.0 scan-surface guardrails for all-skipped inputs, huge copied fixtures, and generated source noise.

## Decision

`gruff.analysis.v2` gains an additive optional `notes?: ScanSurfaceNote[]` field. The field is present only when a scan-surface note exists. Notes are non-fatal and never affect exit codes; `diagnostics` remains the only report surface that drives exit `2`.

Two note types are accepted:

- `no-analysable-files`: a requested input existed but contributed zero supported files, usually because gitignore, default ignores, or config ignores excluded every candidate under it.
- `bounded-deep-scan`: a script file exceeded the deep-scan budget. The file still counts as analysed and text-level rules still run, but deep TypeScript passes, parse diagnostics, and project-source retention are skipped for that file.

The deep-scan budget is `20,000` lines or `2,000,000` UTF-8 bytes, whichever is hit first. This guard belongs in the shared analyser path, not a hook-only adapter.

Generated source policy is marker-based. If one of the explicit generated/copied markers appears in the first 10 lines (`AUTO-GENERATED`, `@generated`, `GENERATED FILE`, `Code generated`, `Generated by`, `DO NOT EDIT`, `Copied from`), gruff suppresses documentation and naming pillar findings only. Security, sensitive-data, size, complexity, maintainability, modernisation, and test-quality findings still run. Path hints such as `fixtures/`, `testdata/`, or `perf-tests/` do not by themselves change rule behaviour.

`gruff.hook.v1` does not gain a `notes` field. Hook findings reflect the same shared analyser decisions, but the hook envelope remains its own stable contract with findings, suppressed count, ignored paths, and config status.

## Context

Adoption-scale scans surfaced three related failures:

- A nested repo path requested from a parent project could analyse zero files and exit clean because a parent `.gitignore` excluded the whole requested tree. That is consistent with ADR-001 and ADR-007 ignore semantics, but silent success misleads the operator.
- A copied TypeScript performance fixture with more than 100,000 lines could consume the whole scan budget in deep script passes.
- Generated `.d.ts` and copied surfaces produced documentation and naming work that no maintainer should perform, while those same surfaces can still leak real credentials or contain unsafe execution.

The repo already treats schema strings, `Finding`, baseline files, default ignored directories, and `gruff.hook.v1` as public-contract boundaries. This decision uses one owner-approved additive `gruff.analysis.v2` field and leaves every other boundary unchanged.

## Failure Mode Comparison

| Option | What fails | Why rejected or accepted |
| --- | --- | --- |
| Keep zero-file scans silent | Operators read "0 findings" as clean even when the requested tree was never analysed. | Rejected. This is the main adoption footgun. |
| Emit diagnostics for all-skipped inputs | Clear signal, but exit `2` would classify ignore-policy outcomes as operational failures. | Rejected. It changes exit semantics for an expected scan shape. |
| Emit advisory findings for all-skipped inputs | Reuses existing report arrays, but invents a pseudo-file finding and churns baselines/fingerprints for a scan-surface condition. | Rejected. A note is the narrower contract. |
| Add optional non-fatal `notes` to `gruff.analysis.v2` | Adds a field consumers may notice, but ordinary reports omit it and exit semantics stay unchanged. | Accepted. It names bounded or empty surfaces without pretending they are code findings. |
| Default-ignore `fixtures`, `testdata`, or `perf-tests` | Reduces noise but hides committed surfaces wholesale, including secrets. | Rejected. Default ignored directories are a public behaviour boundary. |
| Path-based generated policy | Simple, but a directory name can hide sensitive-data and security evidence accidentally. | Rejected. Path alone must not alter rule families. |
| Marker-based docs/naming skip only | Generated code stops demanding maintainer-authored prose, while safety and size checks remain active. | Accepted. It is explicit, narrow, and reviewable in the file itself. |
| Hook-only huge-file handling | Agent hooks get faster but CLI/report/summary disagree. | Rejected. Hook is a view over the analyser, not a separate scanner. |

## Consequences

`src/discovery.ts:discoverSources` must keep producing per-input notes when an existing requested path contributes no files. `src/analyser.ts:scanDiscoveredSources` must keep applying the deep-scan budget per file after source text is read and before expensive script passes.

`src/analyser.ts:analyseSource` remains the central generated-file filter. Future generated-source changes should update that boundary rather than scattering marker checks across individual rule modules.

Documentation and tests must keep stating that generated markers do not suppress sensitive-data/security findings, and that `gruff.hook.v1` has no notes field unless a future owner explicitly approves a hook-contract change.

## Reversibility

The note field is additive but public. Reverting it requires deleting `notes` from `AnalysisReport`, removing discovery and deep-scan note creation, updating text/JSON expectations, and documenting the behaviour change. Generated-marker filtering is easier to reverse internally, but any change that broadens suppression to security or sensitive-data must be treated as a policy change and re-approved.
